# Onboarding

Learn only what makes the system useful now. Ask one short section at a time and accept incomplete answers.

## 1. Outcome

Ask what the owner wants the system to make easier, what repeatedly gets lost, and what the system must never become.

## 2. Collaboration

Ask the owner's preferred name, stable roles, enduring constraints, communication preferences, desired candor, and approval boundaries. Stable agent-facing context belongs in `os/me.md`.

## 3. Current state

Ask for at most three current priorities, meaningful constraints, and open decisions. This belongs in `life/now.md`.

## 4. Durable background

Ask what deeper personal context is genuinely useful. This belongs in one owner file under `life/wiki/`, not in startup context.

## 5. Real work

Identify active personal projects and confirmed businesses. A project starts with one home file. A business gets its own repository only when it is real and independently owned.

## 6. Tools and recovery

Inventory the devices, agent surfaces, repositories, backups, credential systems, and external tools that actually exist. Record no secret values. GitHub is the recommended primary Git host; a second remote and full-device backup are configurable recovery layers.

## Confirmation package

Before editing, show:

1. Stable owner briefing.
2. Current personal snapshot.
3. Exact projects and businesses justified now.
4. Approval, privacy, and publication boundaries.
5. Proposed file and repository map.
6. Deferred items and unresolved risks.

Wait for explicit approval before creating the private system.
