# onboarding interview

**Audience:** Agents
**Lifecycle:** Setup only — archive with the `setup/` folder after onboarding.

**Bottom line:** A conversational interview that learns enough context to fill the existing Life OS documents. It does not redesign the folder system unless the owner's real needs clearly require one small adjustment.

**When to read this:** Read during first setup or an owner-approved context refresh.

## interview behavior

- Ask one short section at a time.
- Let the owner answer naturally by typing, voice, examples, or imperfect notes.
- Ask only follow-ups that materially improve the context files.
- Explain why a sensitive question matters and allow it to be skipped.
- Separate confirmed facts, preferences, hypotheses, and unresolved choices.
- Do not edit files during discovery.
- Use the current top-level structure by default.
- Do not turn every interest, responsibility, source, or desired “agent” into a folder.
- Prefer enough context for the next month over a complete life biography.
- At the end, present the context summary and exact file list; wait for confirmation that it is accurate.

## section 1 — desired change

Learn:

- What should having an agent that knows their context make easier?
- What is currently scattered, repeatedly explained, forgotten, delayed, or avoided?
- What three real examples would feel meaningfully better in the first month?
- What should this system never become?

## section 2 — roles and landscape

Learn:

- preferred name and pronouns
- important work, family, personal, and community roles
- active businesses and clients
- current time-bound projects
- ongoing responsibilities with no finish line
- ideas worth remembering but not activating

Do not infer folder structure yet. Map answers to the existing lanes first.

## section 3 — current state

Learn what belongs in `os/now.md`:

- the small number of current priorities
- open decisions and what would resolve them
- meaningful deadlines or calendar anchors
- current capacity, constraints, or transitions that change planning

## section 4 — how they work

Learn:

- how they start, sustain, switch, and finish work
- attention, memory, energy, and overwhelm patterns they want supported
- preferred amount of structure and explanation
- repeated failure, avoidance, or restart patterns
- approaches that have helped or failed
- accessibility or neurodivergence needs they want represented

## section 5 — information and tools

Learn:

- devices used
- current apps, cloud drives, email, recordings, notebooks, and document locations
- what is the authoritative source for important information
- capture habits: typed, voice, screenshot, email, paper, mobile
- which existing material should remain where it is, be referenced, or be imported later
- which sources contain client, legal, medical, financial, security, or third-party private data

Do not start a bulk import during setup. Create an inventory and privacy plan first.

## section 6 — agent relationship

Learn:

- preferred tone, response length, and teaching style
- when the agent should discuss first versus make a reasonable assumption
- how candidly the agent should challenge a plan
- how many options or priorities feel manageable
- what the agent should proactively notice
- behavior that would feel controlling, vague, intrusive, or unsafe

Keep the starter's plain-language, focused, candid, one-layer-at-a-time defaults unless the owner wants something different.

## section 7 — permissions and privacy

Learn:

- actions that always require approval
- whether local edits are expected after a clear change request
- whether meaningful wraps may automatically commit and dual-push after setup
- archive versus delete policy
- subjects that should load only on demand
- files the agent must not rewrite without specific permission
- legal, medical, financial, security, communication, client, or relationship boundaries

Never ask for passwords, authentication codes, recovery codes, seed phrases, private keys, API keys, or tokens.

## section 8 — retrieval and source truth

Learn:

- information the owner repeatedly needs
- where current truth lives today
- where old versions commonly cause mistakes
- people and topic context that recur across tasks
- which business, client, or project genuinely needs its own local subfolder
- facts that must be externally verified instead of trusted from memory

## section 9 — useful routines

Discuss only routines tied to real behavior:

- daily orientation
- inbox triage
- end-of-work wrap
- weekly reset
- decision logging
- research synthesis
- project handoff
- monthly distillation and maintenance after enough history exists

Leave unused routines as drafts. Do not activate the full supplied skill library automatically.

## section 10 — context summary

Present:

1. Stable owner profile for `os/me.md`.
2. Current-state snapshot for `os/now.md`.
3. Deeper context for `knowledge/people/owner.md`.
4. Collaboration, privacy, and permission rules.
5. Existing folder routes that cover their life and work.
6. Any structure change that is genuinely necessary—and why the existing structure fails without it.
7. Skills to use now, later, or not at all.
8. Source inventory and deferred import risks.
9. Exact files that will change.
10. Important unknowns better learned through real use.

Ask for corrections and explicit confirmation that the context is accurate before personalizing files.
