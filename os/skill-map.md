# skill map

**Bottom line:** Registry and trigger map for reusable routines stored as ordinary Markdown in `skills/`. A supplied routine is available, not automatically active.

**When to read this:** Read at startup. When a task matches a trigger, open that skill—and only that skill.

| skill | trigger | output |
|---|---|---|
| [[inbox-triage]] | `life/00_inbox/` has raw or unclear material | routed notes and blockers |
| [[daily-brief]] | morning or start-of-work check-in | at most three priorities |
| [[eod-wrap]] | end of a meaningful work block | durable updates, repository checkpoints, next action |
| [[weekly-review]] | weekly reset | progress, carry-forwards, and drift check |
| [[distill]] | monthly or on demand | durable signal promoted with receipts |
| [[research-synthesis]] | source-heavy or current question | sourced decision-ready brief |
| [[product-scope-review]] | product, feature, workflow, or UI idea | practical scope critique and next slice |
| [[read-first-code-review]] | code review or audit | evidence-backed findings first |
| [[project-handoff]] | pausing meaningful unfinished work | concise continuity record |
| [[metadata-audit]] | bulk knowledge change or retrieval drift | consistent frontmatter and routes |
| [[decision-log]] | owner confirms a durable choice | dated decision in the owning log |
| [[drift-recovery]] | restart urge or parallel-system drift | return to the existing plan or justify one narrow change |
| [[security-sweep]] | before publication or after unknown intake | severity-ordered findings and blockers |
| [[vault-maintenance]] | monthly or after structural change | validated structure, archive proposals, and backup check |

Add a routine only after repeated use proves it is stable and shared. Business-specific routines stay in their owning business.
